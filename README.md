# 写给一个人 · audience-of-one

> **删干净不等于像人。**
> 一个去 AI 味的 Claude Skill —— 不查词表，把说话的人放回文字里。

![License](https://img.shields.io/badge/License-MIT-green.svg)
![Type](https://img.shields.io/badge/Claude-Skill-orange.svg)
![Lang](https://img.shields.io/badge/lang-中文-blue.svg)

你以为 AI 味是用词问题。其实是 —— **这段话没说给任何人听。**

把"删 AI 词"换成"补回三个坐标"（谁在说、对谁说、为什么非说不可），套话会作为副产品自己消失。名字就是方法：把对所有人说的平均句，改回写给一个人的话。

---

## 为什么需要它

市面上的"去 AI 味"工具做法基本一样：列一张套话清单（赋能、值得注意的是、studies show……），逐条删。删完，文字往往变成另一种 AI 味 —— 干净、平整、没有人。因为它们治的是症状。

这个 Skill 的判断不一样：

> **AI 味的根因，是这段话没说给任何人听。**

语言模型产出的是"对所有人都成立"的平均句。可对所有人都成立的话，对谁都没用。"在当今这个信息爆炸的时代"一眼是 AI，不是这几个字有毒，是因为没有一个具体的人，会对另一个具体的人这样开口。

## 核心方法：补回三个坐标

每段文字都该能回答这三个问题。答不上的那个，就是 AI 味长出来的地方。

1. **谁在说** —— 一个具体、有立场、敢被反驳的人（技术文档里可以是"系统/规范"，非个人，但不能空）
2. **对谁说** —— 一个具体的读者，不是"大家""用户们"
3. **为什么非现在说不可** —— 那句非说不可的话；没有它，就会处处用力、处处没说

三个坐标补上，套话会自己消失 —— 因为一个真人对着另一个真人、为一件非说不可的事开口时，根本写不出那种句子。

## 和别的去 AI 味工具差在哪

| | 常见做法 | 这个 Skill |
|---|---|---|
| 看问题 | AI 味是"用错了词" | AI 味是"没说给任何人听" |
| 核心动作 | 查违禁词表，逐条删（减法） | 补回三坐标，重写成"对人说话"（生成式） |
| 组织方式 | 一张平铺的套话清单 | 每个症状指向"哪个坐标空了"，病因指向改法 |
| 删干净之后 | 容易剩一篇"干净但没人"的稿 | 补坐标＝把说话的人放回来，本就不会变无菌 |
| 防改过头 | 容易把专业文本改成口语 | "坐标可非个人但不能空"——技术文档明确不塞假"我" |

## 安装

```bash
git clone git@github.com:DamomHd/audience-of-one.git
```

把 `audience-of-one` 目录放进你的 Claude Skills 目录：

- 全局可用：`~/.claude/skills/audience-of-one`
- 仅当前项目：`<你的项目>/.claude/skills/audience-of-one`

自包含，无额外依赖，复制整个目录即可用。

## 使用

触发词：去 AI 味、说人话、这段太机器、别像模板、改得有人味、为什么读起来像 AI。

流程很短：

1. **一句话定坐标**：「我把这段读成：**谁** 对 **谁** 说，为了让 ta **怎样**。」填不上的空，就是 AI 味的源头。
2. **逐段体检**：每句对得上坐标吗？对不上的，是哪个坐标空了？
3. **改回坐标，不是删**。
4. **两步回读**（先保真，再查残留）+ **三坐标打分**，过了再交。

## 示例

> **原文**：在当今这个信息爆炸的时代，不可否认，高效阅读已成为现代人的核心竞争力。
> **诊断**：说话人空、听众空、赌注空 —— 三个坐标全空。
> **改后**：我以前一直觉得读得多就是赚。直到有次想跟人复述上周读的东西，发现一句都想不起来。

一条硬红线：改后那句的具体经历，必须来自真作者。**没料时不替作者编**，只给改写的形状，把具体的料要回去。补坐标的真实内容只能来自作者，不能来自模型。

